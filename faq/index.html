That you own what you run: you can run it, change it and keep it without anyone’s permission. Every image is built from its project’s own source at a pinned commit. Where the code was written matters less. Most of these projects are governed from the United States, and what a build from source changes is who you depend on.
Not yet. All 76 are built, audited, tested and scanned, and each has a page with what was measured. The registry they will be published in is not open. The plan is that the latest version of every image is free to pull, with no account.
It is built from the same source: the project’s own, at a pinned commit, under the project’s version tag, and it is tested with the arguments its own Helm chart gives it. Two things differ. What the program does not need is left out: the package manager, and the shell and root user wherever it runs without them. And where a dependency has a fix that the release does not, the image takes the newer one, and its page lists each.
Agents do the work that does not scale by hand: watching for new vulnerabilities, zero-days included, working out which images one touches, proposing the patch and running the build. Agents never hold a signing key, and a person signs off every verdict of “not affected” and every fix that ships. This is how the line is being built; it is not all in place yet.
The aim is Build Level 3, the highest the standard defines: there is no approved level 4. The provenance signed by a hardened builder that level 3 needs is not in place yet.
Because the table shows what Trivy and Grype report, not a number made to look good. 31 of the 76 carry a critical or high finding today. An image’s page lists the ones that are left, where each one is, and why it is still there, most often because no fixed release exists yet.
kubectl debug attaches a shell beside the running container, and each image’s page gives the command. For the same reason an image is not a base image: with no shell a Dockerfile RUN fails, so take the program into your own image with COPY --from.
Ask for it. New images are added on request: send the image and version you pull today, and we will tell you whether and when we can build it.
Two products that are coming and not released yet: Jord, an operating system for Kubernetes nodes, and Innergård, a platform for sites with no way out to the internet. The images need neither. They are ordinary OCI images and run on any Kubernetes cluster.
They are plain Swedish words for fundamental things, because that is what we build. Jord is earth, and Innergård is an inner courtyard: houses all round a yard, with one archway in.
