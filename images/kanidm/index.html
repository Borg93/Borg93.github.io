Trivy reads the modules built into each program; Grype reads the C libraries. A zero means no known finding in what that scanner can read.

Root, shell and open findings

C libraries
1 critical and 3 high, in glibc and the other C libraries the program links. None has a fixed release to take. The critical is CVE-2019-1010022 in glibc, which glibc’s maintainers do not treat as a security bug.

How it was tested

Run on a read-only root, as user 389, with no network beyond its own and no capabilities.

  • Kanidmd served /status over TLS as 389, its database on its volume
  • Kanidmd recover-account gave idm_admin a password through the server's admin socket
  • The kanidm client logged in as idm_admin, and read the group the migration made as the server started
  • It created a group and listed it
  • The domain upgrade check Innergård runs before a new version reported its level, with no FAIL

Pod settings

The image is tested under the first five. With the seccomp profile added, the container meets Pod Security “Restricted”.

securityContext:
  runAsNonRoot: true
  runAsUser: 389
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities:
    drop: [ALL]
  seccompProfile:
    type: RuntimeDefault
